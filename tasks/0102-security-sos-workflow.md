# 0102 — Охрана: SOS и журнал смены

Дата: 2026-10-16.

## Реализовано

- PATCH /sos/:id/accept фиксирует ответственного и время принятия. Повторный запрос того же сотрудника безопасен; конкурирующий сотрудник получает 409. Принятие фиксируется в аудите.
- На веб-странице SOS непринятые вызовы идут первыми, старые раньше новых. Видны ответственный, время принятия и состояния «Ожидает сотрудника» / «В работе». Завершение доступно ответственному; председатель имеет только просмотр.
- Диалог завершения использует общий native Dialog с удержанием фокуса. Результат обязателен в веб-форме, максимум 1600 символов; ошибки показаны внутри диалога. Есть подтверждение сохранения и ссылка на журнал смены.
- Завершение, запись в журнал смены и аудит выполняются одной PostgreSQL-транзакцией. Условное обновление предотвращает повторное закрытие и дубли журнала. При ошибке журнала SOS остаётся активным.
- Запись журнала содержит идентификатор SOS, помещение/жителя при наличии, время вызова и завершения, итог и комментарий. Автор связан с сотрудником. Длинные строки корректно переносятся.
- API теперь запрещает ACTIVE как результат закрытия; ранее IsEnum допускал его вопреки документации.
- Новые ошибки переведены на ru/kk/en в web/mobile; событие SOS_ACCEPTED отображается и фильтруется в веб-аудите.
- Повторный SOS сохраняет сведения об ответственном в realtime payload.

## Совместимость и внедрение

Добавлена миграция 202610160001_sos_acceptance с nullable acceptedById/acceptedAt и FK на users. Существующие вызовы сохраняются. Миграция применена и проверена только на отдельной тестовой БД; перед запуском обновлённого backend в другом окружении требуется штатный prisma migrate deploy.

Мобильный интерфейс принятия в работу этим этапом не добавлен. Для совместимости старый API завершения без предварительного принятия сохранён: если ответственный ещё не назначен, он фиксируется при завершении. Если вызов принят другим сотрудником, закрытие запрещено. Комментарий в старом API остаётся необязательным. Передача принятого вызова другому сотруднику пока не реализована.
