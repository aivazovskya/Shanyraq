# 0099 — Главная по ролям персонала

Дата: 2026-10-16.

## Поведение

- DISPATCHER: срочные обращения (EMERGENCY/HIGH), просроченные по SLA, количество активных и неназначенных заявок; переходы в заявки, чат и журнал смены.
- SECURITY: активные SOS, самые ранние неотработанные вызовы первыми, зарегистрированные точки входа/камеры; переходы к гостевым пропускам, журналу доступа и смене. Финансовые API и заявки других сотрудников не запрашиваются.
- HOA_ADMIN / HOA_CHAIRMAN / SUPERADMIN с привязкой к ЖК: начисления, поступления и собираемость за месяц из Analytics API, количество активных/просроченных заявок, жилой фонд, активные собрания и переходы к расходам и аналитике.
- Без tenantId запросы не выполняются и нулевые показатели не рисуются. Суперадминистратору доступен переход к управлению ЖК. Переключение контекста ЖК в сессии этим этапом не реализовано.

## Логика

- Открытые заявки: PENDING, ASSIGNED, IN_PROGRESS; завершённые/отклонённые исключены.
- Срочные: только EMERGENCY/HIGH, сначала аварийные, затем более ранние по созданию.
- SLA соответствует серверному ServiceRequestsSlaSchedulerService: без обновлений от updatedAt не менее 4/24/72/168 часов по приоритету. createdAt не используется для определения просрочки.
- Данные заявок дополнительно ограничены tenantId, в том числе при глобальном ответе для SUPERADMIN.
- Каждый блок имеет отдельные состояния загрузки/ошибки и повтор. Сбой финансов не скрывает обращения и собрания.
- Оперативные экраны диспетчера/охраны обновляются каждые 30 секунд, пока вкладка видима. Фоновое обновление сохраняет данные до ответа, ошибка заменяет соответствующий блок предупреждением.
- При смене контекста/размонтировании/новом запросе предыдущие HTTP-запросы отменяются; поздние ответы не применяются.
- Отображение зарегистрированных устройств не означает проверки их доступности; этот смысл явно указан в интерфейсе.
- Списки ограничены первыми 5 обращениями/SOS, 6 устройствами, 3 собраниями; счётчики рассчитываются по полному ответу.
- При отсутствии начислений собираемость показана как «—», а не фиктивные 0%.
- Новые тексты ru/kk/en.

## Проверки

Добавлена команда `npm run test:dashboard` на встроенном Node test runner с установленным TypeScript. 8 тестов: матрица ролей/запросов, отсутствие запросов без ЖК и для неподдерживаемых ролей, границы всех SLA, обновление вместо даты создания, открытые статусы, фильтрация ЖК, порядок срочности/просрочки и определение неназначенных заявок. Команда включена в frontend CI перед сборкой.

Новые переводы проверены на наличие ключей ru/kk/en; git diff --check без ошибок. Визуальная приёмка нового экрана по ролям не выполнена: в этой сессии ранее браузерный инструмент заблокировал доступ к localhost политикой доступа. Настоящие аккаунты/БД для проверки не использовались.

Итоговая production-сборка Next.js успешно завершена, включая TypeScript и генерацию 26 страниц.
