## Ключевые расхождения, требующие решения архитектора/продукта

Реализован адаптер `HikvisionIsapiAdapter` по протоколу ISAPI (`PUT /ISAPI/AccessControl/RemoteControl/door/1`) с Digest Auth и таймаутом 5с. Метод `resolveAdapter()` выбирает Hikvision-адаптер только при явном указании `controllerType: 'HIKVISION_ISAPI'`, остальные типы (`PAL_ES` и др.) продолжают направляться в `MockBarrierAdapter`. Добавлены эндпоинты создания точек доступа и проверки связи (`GET /access/points/:id/health-check`). Требуется смоук-тест на реальном домофоне при появлении физического стенда. Шлагбаум/СКУД остаются под мок-адаптером до выяснения вендора.
2. **2FA/PIN/биометрия перед физическим открытием (п. 5.1)** — завершено: [Task 0002](0002-barrier-2fa-pin.md).
3. **Юридическая значимость голосования (открытый вопрос №3) — решено оставить как есть.** Доступа к квалифицированной ЭЦП сейчас нет, HMAC-SHA256 + SMS-OTP остаётся рабочей схемой для пилота. Осознанно принятый риск, не техническое ограничение — вернуться к вопросу при масштабировании на ЖК с риском судебных споров по итогам ОСС.

5. **Финансы (Фаза 2)** — завершена [Task 0006](0006-finance-personal-account.md): базовый модуль лицевых счетов на юнит, настраиваемая тарифная сетка, генерация начислений, ручной приём платежей, баланс и история для верифицированных собственников.
