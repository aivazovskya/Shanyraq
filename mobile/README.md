# Shanyraq Mobile (Expo SDK 58 / React Native)

Мобильное приложение цифровой платформы управления жилыми комплексами и кондоминиумами **Shanyraq** (Шаңырақ).

Приложение разработано на **React Native 0.88 / Expo SDK 58** и поддерживает две основные аудитории:
1. **Жители (Резиденты)** — личный кабинет, подача заявок, чат с диспетчерской, электронные гостевые пропуска, доступ/шлагбаум/домофон, передача показаний счётчиков, онлайн-голосования и прозрачные финансовые отчёты.
2. **Сотрудники управляющей компании и службы безопасности (Staff)**:
   - **Управляющий / Администратор ОСИ (HOA_ADMIN)** — пульт смены, контроль заявок, тревог SOS, журнала доступа и пропусков.
   - **Председатель ОСИ (HOA_CHAIRMAN)** — аналитический пульт, контроль качества заявок, протоколы голосований, финансовые отчёты (режим мониторинга).
   - **Диспетчер (DISPATCHER)** — оперативное распределение и контроль заявок с SLA, обработка чатов жителей и тревог.
   - **Служба охраны (SECURITY)** — оперативный мониторинг SOS-тревог, выписка и сканирование гостевых QR-пропусков, журнал проезда и прохода.

## 1. Быстрый старт и запуск

### Предварительные требования
- Node.js >= 20 (рекомендуется Node.js 22 LTS)
- Запущенный локальный бэкенд Shanyraq API (порт `4000`)
- Docker-контейнеры PostgreSQL (`:5433`) и Redis (`:6379`)

### Установка зависимостей
```bash
cd mobile
npm install
```

### Режимы запуска

#### Web-превью (для разработки и E2E тестирования)
```bash
npm run web
# или: npx expo start --web
```
Приложение будет доступно по адресу `http://localhost:8081`.

#### Запуск на физическом устройстве через Expo Go
```bash
npm start
```
Отсканируйте отображаемый QR-код в приложении **Expo Go** (iOS / Android), находясь в одной локальной Wi-Fi сети с компьютером.

#### Сборка и запуск на эмуляторах
```bash
npm run android   # Android Emulator (обращение к API через 10.0.2.2:4000)
npm run ios       # iOS Simulator (обращение к API через localhost:4000)
```

## 2. Вход в систему (Dev-режим, роли и демо-пользователи)

Вход осуществляется по номеру телефона и одноразовому SMS-коду (OTP). В dev-окружении бэкенд работает с `DEV_OTP_ECHO=true`.

### Демо-аккаунты (создаются в `backend/prisma/seed.ts`)

| Роль | Телефон | Назначение |
|---|---|---|
| **Житель (Resident)** | `+77015550101` | Квартира, заявки, пропуска, чат, голосования |
| **Управляющий (HOA_ADMIN)** | `+77001000001` | Полный доступ к операциям ЖК |
| **Председатель (HOA_CHAIRMAN)** | `+77001000002` | Аналитика, отчёты, протоколы (read-only) |
| **Диспетчер (DISPATCHER)** | `+77001000003` | Заявки, чаты, SLA дедлайны |
| **Охрана (SECURITY)** | `+77001000004` | SOS тревоги, гостевые пропуска, КПП |

### Получение OTP-кода в Dev:
1. В интерфейсе приложения код отображается во всплывающем Toast-уведомлении.
2. В Redis:
   ```bash
   docker exec shanyraq-redis redis-cli GET "otp:<номер_телефона>"
   # Пример: docker exec shanyraq-redis redis-cli GET "otp:+77015550101"
   ```

### Сброс лимитов запросов (Rate Limiting) в Dev:
Сбрасывайте лимиты **точечно** (без вызова `FLUSHALL`):
```bash
docker exec shanyraq-redis redis-cli DEL "otp:+77015550101"
# Очистить ключи ratelimit:
docker exec shanyraq-redis redis-cli --scan --pattern "ratelimit:*" | ForEach-Object { docker exec shanyraq-redis redis-cli DEL $_ }
```

## 3. Переменные окружения

Файл примера: `.env.example`.

| Переменная | Описание | Значение по умолчанию |
|---|---|---|
| `EXPO_PUBLIC_API_URL` | Базовый URL API бэкенда | `http://localhost:4000/api/v1` (dev fallback) |

### Логика определения API URL:
1. `EXPO_PUBLIC_API_URL` имеет наивысший приоритет во всех средах.
2. В dev (`__DEV__`): если переменная не задана, хост вычисляется динамически:
   - Физическое устройство Expo Go: локальный IP хост-машины из `hostUri`;
   - Android Emulator: `http://10.0.2.2:4000`;
   - iOS Simulator / Web: `http://localhost:4000`.
3. В production release (`!__DEV__`): если `EXPO_PUBLIC_API_URL` не задан, приложение выводит понятный экран `ConfigErrorScreen` и ошибку в лог, **не обращаясь молча к localhost**.

## 5. Дизайн-система и правила разработки

### Дизайн-токены и Темы
- Токены определены в `src/theme/tokens.ts`: цвета, типографика (шрифт Inter), радиусы, отступы, тени и анимационные пружины.
- Поддерживается **светлая (Light)** и **тёмная (Dark)** темы. В `app.json` включен режим `"userInterfaceStyle": "automatic"`.
- Контрастность текста и статусных бейджей во всех темах строго удовлетворяет **WCAG AA (>= 4.5:1)**.

### UI-кит (`src/components/ui/`)
- `Button`: варианты `primary`, `secondary`, `outline`, `ghost`, `destructive`; размеры `sm`, `md`, `lg`; тактильный отклик (haptics); минимальная интерактивная область 44×44 pt.
- `Card`: интерактивные и статические карточки с плавной анимацией нажатия.
- `Input`: плавающий лейбл, состояния фокуса, валидации, accessibilityLabel.
- `Badge`: статусные бейджи (`subtle`, `solid`, `outline`) для заявок, SOS и пропусков.
- `EmptyState`: информативный экран при отсутствии записей.
- `Skeleton` / `SkeletonList`: плейсхолдеры загрузки данных с шиммер-эффектом.
- `BottomSheet`: доступные модальные шторки для мобильных устройств.
- `AnimatedEntrance`: каскадное появление списков с учётом `useReducedMotion`.

### Строгие правила кода:
1. **Никаких захардкоженных цветов**: все цвета берутся из `theme.colors.*`.
2. **Никаких захардкоженных строк**: все тексты оформляются через `t('key')` с паритетом в `kk.json`, `ru.json`, `en.json`.
3. **Безопасные отступы под таббар**: на экранах списков обязательно используется хук `useTabBarInset(extraPadding)`.
4. **Доступность (A11y)**: у всех интерактивных элементов заданы `accessibilityRole`, `accessibilityLabel` и размер касания не менее 44×44 pt.
5. **Клавиатура**: все формы ввода оборачиваются в `KeyboardAvoidingView` с `keyboardShouldPersistTaps="handled"`.

## 7. Известные ограничения локального окружения
- Локально хранилище MinIO / S3 не запущено. Загрузка фото в заявках при отсутствии S3 возвращает честную ошибку сети/бэкенда (400), при этом формы создания заявок, показаний и объявлений без фото работают полноценно.
