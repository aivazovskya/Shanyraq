# Проверка Android

## Запуск на телефоне в одной Wi-Fi-сети

Из каталога `mobile`:

```powershell
npm run start:device -- --api-port 4410
```

Команда выбирает Wi-Fi IPv4 компьютера, проверяет `/health` и запускает Metro
на порту 8183 с правильными адресами API и WebSocket. При нескольких сетевых
адаптерах укажите адрес явно: `--host 192.168.1.84` (адрес может измениться).
Для проверки без запуска: добавьте `--check`.

Подключите телефон к той же сети. Откройте на телефоне
`http://192.168.1.84:4410/health`, затем отсканируйте QR Metro совместимой версией
Expo Go. Если health не открывается, проверьте изоляцию клиентов Wi-Fi и доступ
Windows Firewall к серверу; команда не меняет эти настройки автоматически.
`localhost` на телефоне означает сам телефон, а не компьютер.

Для авторизации нужен тестовый номер, настроенный в тестовом backend/SMS-провайдере.
Фикстуры из `preview` работают только в веб-галерее и не дают настоящую сессию.

## Тестовый APK

В `eas.json` подготовлен профиль `preview` для APK. Для облачной сборки нужны
учётная запись Expo, привязанный EAS-проект и доступный с телефона тестовый API
с HTTPS. Задайте `EXPO_PUBLIC_API_URL` (полный адрес с `/api/v1`) в окружении
сборки EAS. Не помещайте секреты в `EXPO_PUBLIC_*` — они попадают в приложение.
`EXPO_PUBLIC_SOCKET_URL` необязателен: по умолчанию используется origin API.

После настройки окружения:

```powershell
npx eas-cli build --platform android --profile preview
```

Не используйте адрес `localhost` или `10.0.2.2` в APK для физического телефона.
Веб-превью и экспорт Hermes-бандла не создают APK. Для локальной нативной сборки
нужны JDK и Android SDK; в текущем окружении они не установлены.

## Проверки на устройстве (ещё не выполнены)

- Клавиатура: телефон, SMS, заявка, чат, показания, пропуск и заметка смены.
  Поле и отправка доступны; первое Back закрывает клавиатуру.
- Back в модалках закрывает только модалку; выход из несохранённой формы
  запрашивает подтверждение. Back на корневом экране проверяется отдельно.
- Размер экрана 320 dp, системный шрифт 100%, 150%, 200%, жестовая навигация
  и системные кнопки: текст читается, действия доступны, safe area соблюдена.
- Потеря связи: сохранённые данные не исчезают, формы сохраняют черновик,
  после восстановления возможен повтор. При тайм-ауте сначала проверить результат,
  чтобы не повторить уже обработанную сервером операцию.
- Камера: отказ, повторный отказ, выбор из галереи, отмена выбора, неудачная
  загрузка, повтор и удаление ожидающего фото. Микрофон не запрашивается.
- Геолокация SOS: отказ и задержка не блокируют отправку сигнала; проверять
  только с согласованными тестовыми данными, без реального экстренного вызова.
- Внутренние уведомления: прочтение и переходы для каждой роли.
  Системные push требуют отдельной настройки: `expo-notifications` и регистрация
  push-токена сейчас не реализованы в мобильном приложении.

## Уже выполнено в веб-превью

Галерея `http://localhost:8182/?role=DISPATCHER&failure=offline` позволяет
проверить сообщение об отсутствии связи при отправке. `failure=timeout`
проверяет тайм-аут. Все реальные запросы галереи блокируются, чтение использует
фикстуры. Это имитация ошибки отправки, а не проверка авиарежима устройства.
